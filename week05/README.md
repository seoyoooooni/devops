# Week 05

## 학습 목표

- 가상 머신과 컨테이너의 실행 환경을 비교한다.
- Docker 이미지·컨테이너·레지스트리의 관계와 컨테이너의 수명주기를 이해한다.
- 포트 매핑과 컨테이너 내부 변경 사항의 저장 범위를 설명한다.
- GitHub Issue에서 시작해 브랜치와 Pull Request를 거쳐 병합하는 흐름을 익힌다.

### 컨테이너의 개념

- 가상 머신은 각각 게스트 운영체제를 실행한다. 
- Linux 컨테이너는 애플리케이션과 실행에 필요한 파일을 묶어 Linux 커널을 공유한다. 
- Docker 이미지는 컨테이너를 만드는 읽기 전용 템플릿이고, 컨테이너는 이미지에서 생성한 실행 인스턴스다. 
- 레지스트리는 이미지를 저장하고 공유하는 곳이다.

### 실행과 관리

- `docker run` 컨테이너를 만들고 실행한다. 
- `docker ps` 실행 상태를 확인한다. 
- `docker logs` 실행 기록을 보여준다. 
- `docker exec -it` 실행 중인 컨테이너 안에서 명령을 수행할 때 사용한다. 
- `stop`, `start`, `restart`, `rm` 컨테이너의 수명주기를 관리하는 명령어다.

- 컨테이너를 실행할 때 이름, 포트, 환경 변수 등을 지정할 수 있다. 예를 들어 `-p 8080:80`은 호스트의 8080 포트를 컨테이너의 80 포트에 연결한다. 이미 사용 중인 호스트 포트를 다시 지정하거나 기존 컨테이너 이름을 재사용하면 충돌한다.
- 컨테이너 안에서 직접 수정한 파일은 그 컨테이너를 삭제하면 사라진다. 
### Issue에서 병합까지

GitHub Issue에 할 일을 기록하고 해당 작업용 브랜치를 만든다. 변경 내용을 커밋해 Pull Request를 열고 검토와 수정을 거쳐 병합한다. Issue 번호를 PR에 연결하면 자동 종료할 수 있다.
