# Week 04

## 학습 목표

- 파일과 로그를 찾고 셸 스크립트로 반복 작업을 자동화한다.
- 프로세스와 PID의 관계, Git 브랜치와 Pull Request를 이용한 협업 과정을 이해한다.
- IP 주소·포트·DNS의 역할을 설명하고 로컬 웹 서버의 연결 상태를 살펴본다.


### 셸 검색과 자동화

- 절대 경로는 루트 디렉터리부터, 상대 경로는 현재 위치부터 파일을 가리킨다.
- `find`는 파일을 찾고, `grep`은 파일이나 로그에서 문자열을 검색한다. 
- 파이프(`|`)를 사용하면 앞 명령의 출력을 다음 명령의 입력으로 전달할 수 있다.

- 셸 스크립트에서는 변수와 실행 인자, 조건문, 반복문을 조합해 같은 작업을 자동화한다.
- 백업은 `tar.gz` 파일을 만드는 것으로 끝나지 않는다. 압축 파일의 내용물을 확인하고 다른 위치에 복원해 원본과 비교해야 실제로 사용할 수 있는 백업인지 알 수 있다.

### 프로세스

- 실행 중인 프로그램은 프로세스이며 각 프로세스에는 PID가 있다. 
- 백그라운드에서 실행한 작업도 PID로 상태를 확인하고 필요한 프로세스만 종료할 수 있다.

### Git 협업

- Git 협업은 기능 브랜치에서 변경 사항을 커밋하고 Pull Request를 열어 검토한 다음 병합하는 흐름이다. 같은 부분을 서로 다르게 수정했다면 병합 충돌을 해결해야 한다.

### 네트워크와 로컬 서버

- IP 주소는 통신할 장치를, 포트는 그 장치에서 사용할 서비스를 구분한다.
- DNS는 도메인 이름을 IP 주소로 해석한다. 

- HTTP 응답은 `curl`로, 열린 포트와 연결된 프로세스는 Linux의 `ss`나 macOS의 `lsof`로 살펴볼 수 있다. 
- 이미 사용 중인 포트에 서버를 하나 더 띄우면 포트 충돌이 발생한다. 
- `ping` 응답이 없더라도 HTTP 서비스는 동작할 수 있으므로 확인 목적에 맞는 명령을 사용한다.
